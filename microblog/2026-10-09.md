# Concatenating fields in JSON lines output using `jq`

## Scenario
You've got some data in JSON lines format, probably some logs. The structure looks something like
this (with the JSON formatted for clarity):
```json
{
  "foo": "a",
  "bar": "b",
  "baz": "c",
  "quux": "d"
}
{
  "foo": "e",
  "bar": "f",
  "quux": "g"
}
{
  "foo": "h",
  "bar": "i",
  "baz": "j",
  "quux": "k"
}
```

And so on.

You want the values for the `foo`, `bar` and (where it exists) `baz` keys in raw output (which is
useful if at least one of these fields is raw text with escaped newlines and tab characters).

## Solution
```
jq -r '.foo, .bar, .baz // empty' < logs.json
```

The comma operator will take the same input and pass it in to each filter in turn, and then
concatenate the outputs of the filters per input item. The comma operator by itself is sufficient if
you know if all of the keys you've selected will appear in each JSON object in the input; however if
a key in your filter is not present, `jq` will output `null` for that key:

```sh
$ jq -r '.foo, .bar, .baz' < logs.json
a
b
c
d
e
null
...
```

This is what the "alternative operator", `//`, is for; for all the values on its left-hand side, it
filters out any which are `false` or `null`. In the case that _all_ of the values on the left-hand
side are `false`/`null`, it outputs the value on its right-hand side. This isn't necessary in my
hypothetical use case where at least one of my keys is in every object in the input; so I just set
the right-hand side to be the no-op `empty`.

However, this functionality of the alternative operator can be useful for signalling when an object
doesn't have any of the keys you were looking for:

```sh
$ jq -r '.non, .existent .keys // "Keys not in input"' < logs.json
Keys not in input
Keys not in input
...
```
